What I do

Hands-on work, from the cabling plan to the runbook. I build it, I document it, and I make sure the next person can run it.

Network design and segmentation

I lay out networks so a problem in one place can't spread to the rest. I group devices into zones by what they are and who uses them, and only firewall policy can connect those zones.

  • VLAN design, inter-zone policy, NAT and site-to-site and remote-access VPN
  • Juniper SRX and UniFi gateways, switching and wireless
  • Redundant DNS behind a virtual IP, with local name resolution that survives failover

Securing systems

Hardening, review and detection. I read firewalls rule by rule, find what is open that shouldn't be, and put IDS and SIEM where they'll catch what matters.

  • Firewall and NAT audits from live counters, separating live rules from dead ones
  • Suricata and Wazuh deployments, tied to threat intel and case management
  • Trusted mail for alerts: SPF, DKIM and DMARC, so warnings actually arrive

Infrastructure and virtualisation

The platforms everything else runs on, set up to stay up. When they do fail, I find out why.

  • Proxmox VE clusters with HA, SDN and ZFS, and offsite backup
  • Root-cause investigations written up as incident reports with mitigations
  • Windows Server and Active Directory, Linux services, monitoring with Prometheus and Grafana

Network disaster recovery plans

This is the work I'm proudest of. A plan that only exists in someone's head fails the day that person is away. I write recovery plans that someone else can follow under pressure. They say what fails, what takes over, who does what and in which order, and how to prove the standby works before you need it.

  • Standby equipment that carries the live configuration
  • Recovery steps in order, with checks after every step
  • Inventory, contacts and configuration sources kept inside the plan
  • Tests that prove the standby works, run before an outage instead of during one

Security tooling

Open source tools I wrote for teams that can't send their logs to someone else's cloud. Most install as one package and need nothing from the internet at runtime.

Pantomath

A threat-intel aggregator. It polls the feeds you choose, scores severity, pulls out CVEs, IPs, hashes and emails, and flags what affects the products you actually run.

  • Marks anything on CISA's Known Exploited Vulnerabilities catalogue
  • IOC database from abuse.ch and AbuseIPDB feeds, with a lookup API for SIEMs
  • Wazuh integration that alerts when an agent touches a known indicator
github.com/dzidulajubilee/Pantomath
Python · JSv1.4.3

Heimdall

An airgapped IDS dashboard for Suricata. Alerts reach the browser over Server-Sent Events the moment Suricata writes them, ready for triage.

  • Per-alert status, analyst notes and a timestamped activity log
  • Signature knowledge base linked to CVEs and MITRE ATT&CK
  • Suppression at ingest, webhooks, and roles enforced at the API

    Watcher

    A broader Suricata console. Alongside alerts it streams every flow, DNS and HTTP record, so you can follow an alert to what the host actually did.

    • Coverage-gap view of signatures that fire most and have no explanation yet
    • Charts over 24 hours to 90 days, and webhooks with per-signature cooldown

    Wazuh integrations

    Small, single-purpose bridges from Wazuh to the rest of a SOC. Each one is a script and a rule file you drop onto the manager.

    • Yeti: checks every observable in an alert and raises a level 12 alert on a match

    • Casebender and n8n: forward alerts into case management and workflows

    About

    I work where networking, systems administration and security meet. Organisations bring me in to build a network, lock it down, and make sure it recovers when something breaks.

    I like infrastructure that is boring in the best way. Zones are clearly separated, failover has been tested, and the documentation matches what's actually running. When something does go wrong, I want the cause in writing and a fix on every affected machine, not just the one that fell over.

    When off-the-shelf tools don't fit, I build my own. The ones above are open source, most under AGPL or MIT.
